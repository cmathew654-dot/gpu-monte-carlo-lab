# Documentation Instructions

Applies to `docs/**` in addition to the repository root guidance.

- Every quantitative claim names its convention and comes from code, dataset
  metadata, a test, or a reproducible command.
- Never invent demo numbers. Capture current validation output and state path
  count, seed, model, and date.
- Contract changes are additive amendments with authorization, measured
  justification, exact surfaces affected, compatibility impact, and tests.
- Keep `MEMORY.md` as the current index; plans, decisions, contracts, and
  calibration remain separate canonical documents.
- Mark proposals and future work explicitly; do not write planned behavior in
  the present tense.
- Prefer short links to canonical evidence over copied logs.
- Update `reviewed_at`/status metadata when meaning changes, not for cosmetic
  edits.
- Preserve honest limitations and environment-specific blockers.
